The **ERITS geospatial pipeline** is a fully automated system for processing, enriching, and analyzing land-related datasets for **Lang’ata subcounty**. Built on a containerized **Apache Airflow** setup, it orchestrates a sequence of well-structured task groups that handle everything from **data extraction** to **final  outputs**. The process starts by preparing multiple geospatial feature layers—such as cadastre parcels, water connections, power meters, buildings, addresses, and development permits—then assigning each land parcel a **globally unique identifier (UUID)**. These UUIDs are used in linking datasets together through spatial joins. Depending on data size and resources, the pipeline can run in **Apache Spark** mode for distributed processing or fall back to **GeoPandas** for smaller workloads.It uses **Parquet files** for fast, efficient data sharing between tasks without repeatedly querying the database. The pipeline then aggregates feature counts per parcel, merges them into a single enriched cadastre table, and calculates a **fusion score** that indicates the likelihood of rental activity based on infrastructure and development indicators. Additional enrichment steps bring in **property names, land ownership records, land rate data, and trade license information**, producing a dataset that is both spatially and contextually rich.

Once all enrichment is complete, the pipeline performs a final cleanup—removing duplicates, dropping unnecessary fields, and validating data integrity—before publishing the results to the **Gold schema** for production use.The architecture uses **PostgreSQL/PostGIS** for spatial storage, **Redis** for task brokering, and **CeleryExecutor** for parallel task execution in Airflow. Grouping operations into distinct stages—such as parquet handling, data preparation, UUID generation, linking, aggregation, interest joining, and final migration—keeps the DAG clean, maintainable, and easy to troubleshoot.
